## 二、关键架构事实（改代码前必读）

- **单写者铁律**（docs/thread-model.md）：会话状态只能在写者线程改。手动模式（loopGroup=null，默认）调用线程即写者；实时模式（`groma.engine.event-loop-threads>0`）经 `TickEventLoopGroup` + `resumeForBurst`。外部干预一律走 `AbstractWorldSession.submitCommand` 桥（`GromaMcpEnginePortImpl.onWriter`）
- **事件总线**：`GromaWorldContext.fire(...)` → `enqueueMemberEvent` → `dispatchSingleEvent`（触发接线表 + traceListener）。新增的双视角事件辅助都在这条链上
- **模型注册中心**：`GromaModelRegistry`（bootstrap）统一合包 ServiceLoader + 热挂载租约；会话级租约经 `GromaSessionManager.SessionLifecycleListener` 停止时释放；流水线构建后回调 `ModelToolRegistrar.onModelMountedAsync`
- **Jackson 3**：包名是 `tools.jackson.*`（非 com.fasterxml），抛**非受检**异常（catch RuntimeException 不要 catch IOException）
- **Web 容器**：内嵌 Tomcat + JSR-356 程序化端点；端点依赖经 `ServerEndpointConfig.getUserProperties()` 注入（**static volatile 桥接已删除**，别再加回来）
- **构建**：`JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ~/tools/apache-maven-3.9.9/bin/mvn -o -f groma/pom.xml test`；**子模块跑测试必须带 `-am`**（否则本地仓库旧构件报 NoClassDefFound）；**增量编译会漏报**（改 record 组件后要 clean test-compile 验证测试构造点）；pom 改动必须跑 XML 校验（曾踩过重复标签且 grep 只筛 .java 漏掉 pom 报错的坑）
- **测试改动纪律**：本轮所有收割都被回归测试把关过（两次抓错：List.of(null) NPE、场景兜底混入占位实体）——**回归不是形式，是收割裁判**
